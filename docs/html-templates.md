# HTML mailing templates

Open Plantillas to paste a complete HTML document or load .html/.htm/.txt. Name it to save it in the reusable library, or choose Usar en una nueva campaña. The editor also offers Importar HTML and Editar HTML. Applying edited source preserves the current subject/preheader; using a template starts a new draft and derives initial details from its title/hidden preheader.

Templates remain HTML designs with a code editor. Arbitrary imported markup is not converted to visual drag-and-drop blocks. Existing visual campaigns remain available. Limits are 250,000 source characters, 1 MB per uploaded file and 100 templates per library. External images require public HTTPS URLs; no images are downloaded or hosted by this import flow.

The shared compiler handles preview, export and SMTP snapshots. It parses imported HTML, permits email layout tags/attributes, removes active elements/event handlers, validates URLs and restricts CSS declarations/functions. Stylesheet selectors are scoped to the imported wrapper. An ordinary readable unsubscribe anchor with the signed placeholder replaces the default footer. The compiler falls back to a separate footer when the anchor is missing, empty, inside a conditional comment or has detectable hiding styles. Imported CSS cannot select the separate fallback footer. Compatible media queries and sanitized conditional Outlook VML buttons are retained; Office XML settings and unsupported CSS are omitted. Actual Outlook/Gmail/Apple Mail rendering has not been verified.

Preview uses a sandboxed iframe and restrictive CSP. Remote images are blocked until the operator chooses Mostrar imágenes externas. Scripts, forms, embedded frames, external stylesheets, CSS imports and CSS URL fetches are removed. The compiler does not fetch external resources.

Common Brevo unsubscribe/FIRSTNAME/EMAIL aliases become MailCraft variables. The simple FIRSTNAME conditional wrapper used by the supplied example is removed while retaining its content. Unsupported template logic/variables produce an actionable validation error. Brevo mirror links become {{mirror_url}}. Preparing an authorized SMTP preview creates a purpose-signed URL under /email-view/ for the immutable, personalized message snapshot. Tampered signatures, wrong tenant/message combinations and unsubscribe tokens are rejected. Browser views use no-store/noindex/referrer protection, CSP and a sandbox. Anyone with the signed URL can view that message, as with forwarding the email; links stop working if the message is removed. In the editor, mirror/unsubscribe anchors are inert placeholders until preparation. Public reachability still requires the configured public application origin. Imported unsubscribe links and the mandatory footer use signed contact-specific URLs when preparing an authorized SMTP preview. Contact substitutions are escaped as HTML text.

Authenticated library records use the existing EmailTemplate table and tenant context from verified sessions. List/read/create queries include tenant_id, and viewer writes remain forbidden. No database migration is required for this feature. In labeled demonstration mode, templates and drafts are stored only in the browser.

Verification: 20 unit tests; API smoke for reusable templates, source validation and cross-tenant reads; isolated simulated SMTP for escaped HTML personalization and signed unsubscribe; successful Angular/NestJS builds in Docker. The supplied 10,449-character Reclamo Fácil HTML was processed and opened in the local browser without sending mail. Its tables, media queries, VML button and name substitution were detected in compiled output. A reusable copy and campaign were saved in the local browser demonstration only.
